# 脱敏说明

> 这份文档解释：公开版删了什么、替换了什么、怎么验证的，以及还剩哪些风险。

---

## 1. 为什么要脱敏

原始项目是一个真实在用的 QQ 对话机器人，仓库里包含：

- 几十万字的示例对话记录；
- 由聊天记录蒸馏出的配置原文、记忆、训练数据；
- 示例对象音色的 TTS 权重与参考音频；
- 本地模型（7GB+）、数据库（1GB+）、截图、二维码；
- 真实 API key、Dashboard 密码、服务器地址、QQ 号；
- 真名、地名、学校/工作相关信息。

这些内容即使「打码」也不适合公开：几十万字无法可靠逐条脱敏，模型/语音文件也超出 GitHub 限制。所以公开版采用**删掉原始数据 + 替换代码中的标识符**，而不是「把聊天记录打码后上传」。

---

## 2. 删除了什么

| 类型 | 例子 | 处理 |
|---|---|---|
| 聊天记录 | 私聊/群聊全记录、聊天提取、群相关对话 | 全部不发布 |
| 配置原文 | `persona.txt`、配置草案、配置快照、配置补丁脚本 | 全部不发布；另写虚构示例 |
| 记忆 | 记忆卡、回忆录、事件记忆导出 | 全部不发布 |
| 训练数据 | `*.jsonl` 训练集、蒸馏数据 | 全部不发布 |
| 语音/音色 | 参考音频、TTS 权重、音源、试听 | 全部不发布 |
| 模型 | `*.gguf`、`*.safetensors` 等 | 全部不发布 |
| 数据库 | `*.db`、`*.db-wal`、`*.redb` | 全部不发布 |
| 截图/二维码 | 聊天截图、桌面截图、登录二维码 | 全部不发布 |
| 备份 | `backups/`、恢复测试目录 | 全部不发布 |
| 第三方目录 | NapCat、GPT-SoVITS、ffmpeg、Python 运行时、模型目录 | 全部不发布 |
| 运行日志 | `astrbot_run*.log`、`butler.log`、`watchdog.log` | 全部不发布 |
| 评测报告 | `ops/eval/reports/` 下的生成结果与分数 | 全部不发布 |
| 私有 holdout | 真实 case、freeze manifest、盲测 key | 全部不发布；另给合成样例 |
| 真实评测数据 | `cases.jsonl`、`holdout_v*.jsonl` | 全部不发布 |

> 原始目录（约 23 GB）保持不动；公开版是从中**按 allowlist 复制**出来的一个小仓库。

## 3. 替换了什么

| 原始 | 替换为 | 说明 |
|---|---|---|
| 真实姓名 / 昵称 | Bot / User / OtherUser | 虚构 |
| 其他真实人名 | 他人A / 他人C / 他人D | 仅用于「不要串名」的过滤测试 |
| 真实地名 | ExampleCity | 虚构城市 |
| QQ 号 | `100000000` / `100000001` / `100000002` | 占位 |
| 邮箱 / 手机号 | `user@example.com` / `138****0000` | 占位 |
| 实例 UUID | `11111111-1111-4111-8111-111111111111` | 固定占位 |
| Windows 路径 | `D:\demo`、`D:\demo-build`、`D:\napcat` | 占位 |
| 项目代号 | `demo` / `DEMO_*` | 从原名改为中性代号 |
| 管家文件名 | `butler.py` | 原名含角色名 |
| API key / 密码 | 不发布；`.env.example` 只给空值 | — |
| 关系时间线 | 「阶段 A / 阶段 B / 近期」 | 去掉真实月份与事件 |
| 语料规模描述 | 「示例语料 / 约 1,800 条」 | 不暴露原始语料细节 |

## 4. 怎么做的

1. **Allowlist 复制**：只复制 `ops/`、`patches/files/astrbot/`、根目录的代码/构建文件；按扩展名和目录排除数据。
2. **自动替换**：路径、名字、QQ、UUID、代号、关系阶段标签。
3. **正则扫描**：扫 `sk-` / `Bearer` / 邮箱 / 手机号 / 真实人名 / 城市 / `F:` 路径 / 旧 UUID。
4. **人工复核**：逐个看文档与代码注释，修掉「替换后语义不通」的段落（时区、关系阶段、示例命令）。
5. **全量编译**：`python -m compileall` 检查所有 `.py` 无语法错误。
6. **Git 检查**：新仓库从空历史初始化，不推送原始 commit；提交前跑 `git status` 与密钥扫描。

## 5. 验证结果

公开版构建时的检查：

- 真实人名 token：0；
- 真实城市 token：0；
- 旧 UUID：0；
- 真实 QQ/邮箱/手机号：0；

- 体积：约 1.7 MB。

> 这些数字会随文档增加略变，但量级不变。

## 6. 残余风险

诚实地说，仍可能有：

1. **语义残留**：某些测试/注释保留了「对话机器人」的通用语境（生日、冲突、偏好），不是真实对话，但读起来可能像；
2. **代码结构指纹**：文件组织、函数命名、评测阈值仍能看出原始项目的设计；
3. **示例配置**：虽然完全虚构，但格式与原始配置相似；
4. **关系阶段统计**：`style_profile.py` 保留了括号率等统计数字（已去掉真实月份），这些数字本身不指向个人；
5. **无法验证的第三方数据**：`patches/files/astrbot/` 是 AstrBot 的修改副本，上游代码本身不含你的数据。

如果你发现任何能指向真实个人/地点的内容，请开 issue，我会删。

## 7. 给要复用这个仓库的人

- 不要直接把 `examples/persona.sample.md` 当成示例对象；
- 不要用别人的聊天记录训练/克隆声音，除非你有明确授权；
- 不要把自己的 `.env`、数据库、截图提交到公开仓库；
- 部署前先读 [SECURITY.md](SECURITY.md)；
- 如果你要发布自己的版本，建议从空 git 历史开始，并跑一遍 `ops/verify/check_git_secrets.py`。

---

## 8. 原始密钥的处理

原始环境里的 DeepSeek / MiniMax key、Dashboard 密码、NapCat token 曾经以明文形式存在。**公开版不包含它们，但它们在原始机器上仍然有效**。

发布前/后请务必：

```powershell
python ops\dev\rotate_key.py --check
python ops\dev\rotate_key.py --name deepseek
python ops\dev\rotate_key.py --verify
```

并在各 provider 控制台撤销旧 key。只删文件不等于 key 失效。
